## What this is

A multi-tenant HOA relationship management platform. The core value is the **Connection Map**: a force-directed graph showing how residents, properties, businesses, and associations connect to each other. Everything else supports that.

Client is a Savannah, GA homeowners association. Parcel data comes from SAGIS (Savannah Area Geographic Information System).

Built by MANGIA DMA. Reference implementation for the data model is DM Hero (MIT licensed), but we are **not** forking it. We are rebuilding on a different stack.

## Commands

```bash
pnpm install          # install deps
pnpm dev              # vite dev server
pnpm build            # production build
pnpm typecheck        # tsc --noEmit
pnpm lint             # eslint
pnpm test             # vitest run
pnpm verify           # typecheck && lint && test && build

supabase start        # local Postgres + Studio in Docker
supabase stop
supabase db reset     # drop, re-run all migrations, re-seed
supabase migration new <name>
supabase gen types typescript --local > src/types/database.ts

pnpm sagis:harvest    # download the parcel corridor from the county service
```

`pnpm sagis:harvest` writes ~14MB to `data/` and `public/parcels/`, none of it
committed, so a fresh clone has no parcel layer until it runs. The app falls back
to the 60-parcel fixture in the meantime, which works but only covers one street.
Coverage is defined in `scripts/sagis/coverage.mjs` and recorded in
`src/lib/parcels/coverage-manifest.json`. See `docs/SAGIS-API.md`.

`pnpm verify` must pass before any commit. No exceptions.

## Non-negotiable rules

### Data model

- **One `entities` table** with a `type` discriminator and a JSONB `data` column. Do not create per-type tables.
- **One `relations` table** with real FKs to `entities(id)` on both sides. Relations carry `start_date`, `end_date`, and a JSONB `attributes` column.
- Bidirectionality is a **read** concern. Store one row, render both directions using `label` and `reverse_label` from `relation_types`.
- Every table carries `org_id`. Every RLS policy filters on it. No exceptions, including lookup tables.
- Soft delete via `deleted_at`. Archive via `archived_at`. These are different states with different meanings.

### Audit

- The audit log is implemented as **Postgres triggers**, never application code.
- Updates write one row per changed field so history reads as a field-level diff.
- Relation changes are audited too. "Unit 42 changed hands" is the highest-value entry in the log.

### Security

- Never commit secrets. `.env.local` is gitignored. Use `.env.example` with placeholder values.
- RLS enabled on every table from the migration that creates it, not retrofitted later.
- Never write against a remote Supabase project. Local only.

### Code

- TypeScript strict mode. No `any`. No `@ts-ignore`.
- `src/types/database.ts` is generated by the Supabase CLI. Regenerate after every migration, never hand-edit.
- Zod schema per entity type, shared between form validation and API validation.
- No inline SQL in components. Queries live in `src/lib/` or feature-level hooks.

### Writing

- **No em dashes anywhere.** Not in code comments, not in UI copy, not in commit messages, not in documentation. Use commas, colons, or parentheses.
- No hashtags in any UI copy.
- UI copy is written for HOA board members, not developers. "Connection Map" not "chaos graph". "Resident" not "entity".

## Things that are easy to get wrong

- **`property.zoning` and `property.property_use` are two different fields.** Zoning is the regulatory district. Property use is what is actually there. Collapsing them breaks the "commercial use in a residential district" query, which is a core use case.
- **SAGIS PIN has two valid formats.** `20032 63001` with a space, and `10993C01034` where a letter takes the place of the space. Validate both.
- **Jurisdiction is derived, not entered.** PIN starting with `2` is City of Savannah. PIN starting with `1` is unincorporated Chatham County.
- **Board membership is not a separate table.** It is a `member_of` relation with `role: 'board'` in attributes plus term dates. This is what makes board history appear in the Connection Map automatically.
- **The SAGIS outbound URL is a template in org settings**, not a hardcoded string. Municipal GIS viewers get replatformed.
